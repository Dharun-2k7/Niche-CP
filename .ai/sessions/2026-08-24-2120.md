# Session: 2026-08-24 - NicheCP Problem Setter & Judge Pipeline Architecture Upgrade

## Achievements Summary
1. **Security Isolation & Redis Queue Delegation**:
   - Eliminated all host `os/exec` calls in `admin.go` (`GenerateTestcases`, `ValidateProblemInput`, `TestProblemChecker`, `RunSolutionOnInput`).
   - Created `problem_setter_queue` in Redis for delegating problem-setter execution from API server to Docker worker.
   - Enforced ADR 011 security boundaries (zero Docker socket exposure in API container).

2. **Sandbox Engine Enhancements (`backend/internal/judge/sandbox.go`)**:
   - Added `RunWithArgs(input, extraArgs, timeoutSec)` to `DockerSandboxSession` for command-line arguments and customizable timeouts.
   - Added `InjectFile(containerPath, content)` to `DockerSandboxSession` for writing testcase input files into container tmpfs `/tmp`.
   - Added `ExitCode` field to `SandboxResult`. Added NsJail parity methods.

3. **Checker Engine Abstraction (`backend/internal/judge/evaluator.go`)**:
   - `RunStandardChecker`: Token-by-token comparison with normalized whitespace handling.
   - `RunFloatChecker`: Floating-point token comparison supporting absolute & relative epsilon tolerances.
   - `RunCustomChecker`: Sandboxed C++/Python custom checker script execution with input/expected/actual files injected.

4. **Worker Problem Setter Pipeline (`backend/cmd/worker/main.go`)**:
   - Added `problem_setter_queue` to worker Redis listener.
   - Built `processProblemSetterJob` supporting `ps_run`, `ps_generate`, `ps_validate`, `ps_run_solution`, `ps_run_checker`.
   - Serial session lifecycle (compile → start → run → close) ensuring semaphore resource limits are never breached.
   - Updated `processSubmission` to load from `testcases` relational table with fallback to legacy `hidden_testcases` JSONB.

5. **12 Secure API Endpoints (`backend/internal/api/problem_setter.go`)**:
   - `PUT /api/admin/problems/:id/config` & `GET /api/admin/problems/:id/config`
   - `POST /api/admin/problems/:id/generate` (Generator → Validator → Solution pipeline)
   - `POST /api/admin/problems/:id/validate` & `POST /api/admin/problems/:id/run-solution` & `POST /api/admin/problems/:id/run-checker`
   - `POST /api/admin/problems/:id/testcases` & `GET /api/admin/problems/:id/testcases` & `PUT` & `DELETE`
   - `POST /api/admin/problems/:id/review` (Automated 10-point audit checklist)
   - `POST /api/admin/problems/:id/publish` (Sets status = `PUBLISHED` & syncs JSONB fallback)

6. **Polygon Workspace UI Overhaul (`frontend/admin_problems.html`)**:
   - Integrated all 7 Polygon tabs (Overview, Statement, Solution, Validator, Checker, Tests, Review) with backend pipeline.
   - Added status badge (`DRAFT`, `READY_FOR_REVIEW`, `PUBLISHED`), time & memory limits editing, floating point epsilon inputs, individual testcases management table, argument line generator modal, and automated review scan.

7. **Database Schema Extension & Migration (`database/schema.sql` & `database/migrations/001_problem_setter_pipeline.sql`)**:
   - Extended `problems` table with `status`, `time_limit_ms`, `memory_limit_mb`, `checker_type`, `checker_config`, `generator_config`, `validator_config`, `solution_config`.
   - Created `testcases` table with per-test index, source, generator args, validation status, and expected output.

   - Unit tests (`go test ./internal/judge/... -v`) passed with **PASS** across all judge tests (`TestStandardChecker`, `TestFloatChecker`, `TestCppVerdicts`, `TestPythonVerdicts`, `TestSecurityIsolation`, `TestExecutionSemaphore`).
